# exeris-caps-credential-store

Operating contract for AI agents working in this repository.

## 1. Mission and scope

`exeris-caps-credential-store` is a single-module Exeris capability (Layer 5 — Domain primitive (identity)). It provides `CredentialStore`, `AccountVerification`, `CredentialRecovery`. Licence: `commercial` — Exeris Commercial License 1.1, source-available
(ADR-023). It is a proof of concept built against `exeris-kernel` 0.13.0-SNAPSHOT; `README.md` describes
what it does and does not do.

## 2. Operating contract and boundaries

- **The cap-tier Wall (ADR-055), build-enforced.** `eu.exeris.caps.credentialstore.api` is the cross-cap surface and `eu.exeris.caps.credentialstore.internal` is private.
  The package root `eu.exeris.caps.credentialstore` is load-bearing: the guard derives the cap's own name
  (`credentialstore`) from the segment after `eu.exeris.caps.`. Never put an `internal` type in a public
  signature.
- **No host runtime (ADR-006).** No `org.springframework.*`, `jakarta.servlet.*`, `io.netty.*` or
  `reactor.*` import, in main or test sources.
- **Declarations.** The `@CapabilityModule` class carries the whole contract. Do not add a speculative
  `@Requires`: it is an edge in every SKU's composition graph. A behavioural change to a `@Provides`
  service needs a version bump.
- **The committed manifest.** `src/main/generated/java/cap-manifest.json` is tracked and regenerated by
  the build into `src/`. A declaration change commits the regenerated manifest with it.
- **Entitlement.** The cap registers an `EntitlementRequirement` (in `META-INF/services/eu.exeris.kernel.spi.contract.EntitlementRequirement`) whose capability id is `exeris-caps-credential-store`, its artifactId. Keep the id equal to the artifactId (ADR-089).
- **JDK 25, no preview.** `maven.compiler.release` stays 25; no `--enable-preview` in any scope.
- **Tests.** JUnit 5 and AssertJ only; no mocking framework.
- **Safety.** Do not push, tag, publish or change repository settings unless the user asks. The vendored
  bundle policy `bundle:agent-safety-and-autonomy` applies.

## 4. `.agents/` discovery

- `.agents/manifest.yaml` — imports the organisation bundle `exeris-agents`, pinned by version, commit
  and digest.
- `.agents/vendor/exeris-agents-2.1.0/` — the vendored bundle: policies, base schemas and the hook
  dispatcher. Never edit it in place; bumping it means re-vendoring.

This repository authors no profiles, skills, workflows or hooks of its own.

## 5. Verification and reporting

```bash
mvn compile -Dexeris.codegen.skip=true   # pass 1 — seed capability metadata
mvn verify                               # pass 2 — generate, validate the graph, scan the Wall
git status --porcelain                   # must be empty: the committed manifest matches the build
```

The build log must show `Cap-tier Wall clean` with `own cap(s): [credentialstore]`. Report what ran and its
result; do not claim a check that was not run.
